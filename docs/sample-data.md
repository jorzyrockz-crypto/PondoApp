# Sample data preview

Settings → Data → **Load sample data** adds fictional, marked examples alongside the active workspace's records. Examples cover funds, projects and allocations, income and expenses, cash donation, supplier payable, paid and partially paid refunds, itemized refunds, a non-cash refund credit, fictional void history, regular and monthly contributions, project fundraising, and personal and fund-funded Death Aid with a recorded handover. Names and descriptions are labeled `[Sample]`. A generated receipt labeled SAMPLE is stored only on the device by default. Dates are illustrative, not future-dated; monthly periods use the current and previous month.

Sample entries affect balances, dashboards, reports and backups, and can sync to members of a team workspace. Loading and clearing require confirmation and a writable, confirmed workspace; neither is available to a reviewer or a workspace locked for recovery. A workspace, access or record change during confirmation cancels the operation. Only one set of samples can be loaded at a time.

**Clear sample data** removes marked sample records, including edits to those marked records. It never cascades into unmarked records. If an unmarked transaction, payment, allocation, contributor, refund, activity or handover depends on sample data, a sample payment has an unmarked handover, a sample record has a pending request, or a sample refund contains unmarked non-cash credits, clearing is blocked until the dependency is resolved. Clearing is also blocked when the remaining core records would fail financial validation. Back up your records before resolving dependencies. An unmarked historical audit entry is retained. Save failures are reported; follow the storage warning and export the current data before reloading.

An owner can optionally include one real shared editor receipt when online and synced in a disposable team workspace registered with a name beginning `Pondo Sample Test ` followed by a unique suffix. The editable display name does not qualify a workspace. This opt-in requires typing CREATE and uses the normal atomic snapshot/receipt sync and existing rules; confirm team sync before relying on it. The shared receipt document is immutable under ordinary rules and survives Clear sample data; it is not covered by JSON backup or currently removable through the app. Permanent workspace deletion is not available. Use only a disposable workspace; the name check is an accident guard, not a security boundary.

Sample loading does not create team accounts, invitations, member refund inbox requests, reviewer receipt documents, Faculty Fund recovery records, public reports, Storage objects or historical/orphaned records. It is not a complete Firestore deletion test or a substitute for an administrative inventory. Never use fictional entries as real financial records.
